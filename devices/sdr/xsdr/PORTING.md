# xsdr porting ledger

board/RX/TX/rate controls") in detail. Same contract: **Present** means source exists, test
names are definitions, not run results; nothing is hardware-qualified (U). Reference:
`devices/vendor/libusdr/PIN`; `C:` paths are relative to its `lib/`. `O:` = `oracle/tests/`,
`T:` = `tests/`, `P:` = `src/portable/`, `L:` = `../chips/lms7002m/src/` (`lms7002m`).

Golden-line numbers refer to `oracle/tests/golden/xsdr_session.trace` (characterization).

The `Lms7002m` cache is the part of libusdr's `lms7002m_state_t` the ported operations read
(`reg_mac`, `reg_en_dir`, `rfe[i]` path/loopback/enable and gain codes, `trf[i]`
enable/loopback/gain/`lbloss`, the processors' `dscpcfg` and `hbdo_iq` words,
`reg_tbb_gc*`). Not cached: the RBB state, `reg_*tsp_dscmode` (written, never read) and
`temp` (the SXX search's VCO selection, local to the tuning). `lml_mode` is cached once the rate's
`LimeLight` writes complete, as libusdr does. Operations update the cache
before their writes and keep the update when a write fails, as libusdr does; chained
control-code calls are built one at a time, so a failure leaves later calls unbuilt.
`ctrl::Control` is libusdr's `lms7002_dev_t` for the ported operations (the paths
`rx_rfic_path`/`tx_rfic_path`, the bands in use `rx_cfg_path`/`tx_cfg_path`,
`rx_lna_lb_active`, `tx_loss` and the NCO words `rx_dsp`/`tx_dsp` included); the XSDR's
`xsdr_dev_t` fields the rate path reads (`afe_active`, `dpump`, `s_rxrate`, `s_txrate`,
`lms7_*lo_last`) live in `Device`.

Kept as libusdr, not divergences, on the RX stream: a format without `&` reports 0
logical channels, so the first create rewrites the `LimeLight` maps (MIMO unless double
pumped) and a later one does not; the maps are written before the double pump's refusal
of both channels; `siso_sdr_active_rx`, once set by a double-pumped create, is never
cleared, so later rates skip the supply boost; `xsdr_prepare` writes the RX pins and LED
and streams up even when RX already runs, and sets `tx_run` only while a TX stream exists
(then streaming both directions up and calibrating the TX link too); a create on gateware
without a TX MMCM fails in its calibration (`-ERANGE`) after streaming up
(`O:stream_parity.rs::gateware_without_a_tx_mmcm_fails_the_create_after_streaming_up_like_libusdr`); the close
stops a stream's DMA and front end and ignores the result before `xsdr_dtor`; after a
destroy the AFE counts as inactive, so the next rate enables it again.

Kept as libusdr, not divergences: the HWID is read twice (the second read is used); a wrong
PMIC revision does not fail the open; the power-good wait reads both status registers once
and accepts any status (`lp8758_check_pg(.., 0xf, ..)` cannot report not-good); the rails
get libusdr's codes, and the board constants name the voltage SNVSAC6B gives each code:
channel 2's 1280 mV request is code 0x86, 1.285 V (`lp8758` would give 0x85 for 1280),
and channel 3's 1850 mV request is code 0xB3, 1.84 V (20 mV steps, rounded down). At close:
streaming-down skips a failed write's batch without reporting it and reports only its AFE
write (`lms7002m_streaming_down` ignores the other results); `trf_path` sets `EN_DIR_TRF`
from the RX front ends' enables; `LB_LOSS_24` (24) reaches the 2-bit `L_LOOPB_TXPAD_TRF`
masked to 0; a close without power-up writes to the chip in reset, from the zeroed state.
On the rate path: libusdr's LFSR sweep leaves the RX FIFO on the LFSR pattern when RX was
not running before the call (its `set_lmlrx_mode(NORMAL)` runs only for an RX already
running); the badness it compares is the counters' squares summed in 32-bit arithmetic,
unscaled, and only a badness over 100 fails the rate; `lms7002m_afe_enable`'s result is
ignored. In the chip code: the TX mixer bypass is set in the RX register layout (bit 7,
`ISINC_BYP`, not `CMIX_BYP`); the TBB amplifier code clamps an unsigned sum, so a negative
correction larger than the filter code gives 63, and a negative TBB resistor fit 255; the
`LimeLight` processor dividers write `div / 2 - 1` wrapped (0xFF for 1); `rfe_gain` picks
the first code *below* the asked attenuation; `set_gain` passes the TX pad `-10 * gain`,
so a TX gain of −20 dB stores loss code −20 masked to 5 bits; `sxx_tune` leaves the bank
selection on the synthesizer's bank when it fails; the CGEN disable's result is ignored.
The `/dm/sdr/0/rx/frequency` skip compares with the last LO *tuned*, so setting 0 first does
nothing.

Kept as libusdr, not divergences, since 2026-10-21: an XSDR's `fe=none`, or a hint finding
nothing, fails its open with `-ENODEV` (`Error::NoFrontEnd`), the probe's operations made;
the XTRX ignores hints; a timed start (`USDR_DMS_START_AT`) is a start, its time unused, so
none is offered; the RX A/B swap holds only until the next map rewrite (a stream's change of
channel count, a streaming up), which libusdr makes without it; the extended TX core starts
unmuted and unswapped whatever its channels; the XTRX's revision 4 is told from an ID that
reads 0xBEEF or 0xFFFF, so a board without a DAC80501 is taken for one; the DSP chains'
microcode is reloaded only when a factor changes, so a rate of the same factor only pulses
the chains' resets.

## Remaining

A board the automatic probe skips (libusdr logs `Unable to initialize ...` at ERROR) is
logged by `sdr-frontend` at WARN and skipped.

*Public API (pending owner review, 2026-10-21): stream formats.* `Device::create_rx_stream_as(RxChannels, samples_per_packet, WireFormat, SampleFormat)` and `create_tx_stream_as(TxChannels, samples_per_packet, WireFormat, SampleFormat)` (the `ci16` `create_rx_stream` and `create_tx_stream` now call them); `receive` and `send` are generic over the sealed `HostSample` elements (`[i16; 2]`, `[f32; 2]`, `[u8; 3]`, `i16`, `f32`), so existing `[[i16; 2]]` callers compile unchanged; new `WireFormat`, `HostSample`, the re-exported `sdr_formats::SampleFormat`, and errors `UnsupportedFormat` and `HostFormat`. A real wire takes `RxChannels::A` as lane 0 and `B` as lane 1, libusdr's channel numbers, rather than new lane variants. The host format is named at create by a `SampleFormat` rather than a type parameter, so a receive or send can pass other buffers, which `HostFormat` refuses.

*Public API (pending owner review, 2026-10-21): the remaining controls.* `Device::open_with(bus,
&FrontEndSelection)`, `variant()`, the front-end controls (`set_oscillator_dac`,
`configure_pciefe`, `set_sync_calibration_frequency`, `sync_calibration_frequency`,
`set_sync_calibration_path`), the phase overrides (`set_tx_phase_override`,
`set_tx_iq_phase_override`, `set_rx_phase_override`, `apply_tx_phase_override`),
`check_tx_quality`, the stream options (`start_rx_stream_with`, `start_tx_stream_with` with
`StreamSync`, `set_tx_stream_mute` with `TxMute`, `set_tx_stream_channels`,
`set_rx_throttle`, `signal_rx_ready`, `swap_rx_channels`) and the debug controls and
readings (`set_rx_lfsr_checker`, `rx_lfsr_errors`, `set_tx_generator_pattern`,
`set_tx_iq_select`, `set_rx_phy_delay` with `RxPhyDelay`, `capture_rx` with `RxCapture`,
`clock_readings` with `ClockReadings`, `pps_ticks`, `set_usb_clock`, `set_io_voltage`,
`rx_dc_power`, `temperature`); `sdr_frontend`'s option and setting types re-exported; new
errors `NoFrontEnd`, `NoOscillatorDac`, `FrontEndMissing`, `InvalidPhase`,
`InvalidDelay`; `UnsupportedGateware` removed (no gateware is refused any longer).
`Device` closes on drop. `sdr-stream` gains `ExtendedTxPush`, `ExtendedTxWrites`,
`REG_EXTENDED_TX_PUSH`, `MAX_EXTENDED_TX_TIMESTAMP` and `MAX_EXTENDED_TX_ANNOUNCE` (moved
out of `usdr`); the new `sdr-gearbox` holds the FIR gearbox tables (`Factor`,
`UCODE_BYTES`), moved out of `usdr`.

*Public API (pending owner review, 2026-10-19): the TX stream.* `Device::create_tx_stream(TxChannels, samples_per_packet)`,
`start_tx_stream()` (libusdr's `USDR_DMS_START`, then the `"none"` sync),
`send(&[&[[i16; 2]]], Option<u64>, timeout) -> Option<TxTelemetry>` and
`stop_tx_stream()` (stop and destroy), one stream at a time, `ci16` only, as the RX
stream's; new errors `TxClockUnlocked`, `TxClockOutOfRange`, `OutdatedGateware`,
`UnequalChannelBuffers`, `SendSize`, `UnsupportedTimestamp`; `lowlevel` re-exports
`hal`'s `TxCommit` and `TxFill`. `lms7002m` gains `Control::streaming_up_tx`,
`update_bandwidth`, `delay_tx_tsp`, `RateRequest::plan`, the chip operations
`limelight_toggle_tx_clocks`, `limelight_tsp_clock`, `limelight_delays` and the
`ChipCall`s `LimelightTspClock` and `LimelightDelays`. `sdr-stream` gains the original TX
core's `tx_push_words`, `TxCoreStatus`, `extend_drop_count`, `tx_gateware_supported`,
`tx_block_bytes` and its limits, `sdr-stream-sim` the `TxEngine` model (both moved out of
`usdr`/`usdr-sim`, which re-export them). The new `sdr-cal` holds `usdr`'s `cal::{fit,
search}`, its resumable 2-D search's internals (`Search2d`, `Probe2d`, `Golden`, `Line`)
now public for `usdr`'s board to reach.

*Public API (pending owner review, 2026-10-18): the RX stream.* `Device::create_rx_stream(RxChannels, samples_per_packet)`,
`start_rx_stream()` (free-running: libusdr's `"none"` sync, then `USDR_DMS_START`),
`receive(&mut [&mut [[i16; 2]]], timeout) -> RxPacket` and `stop_rx_stream()` (stop and
destroy), one stream at a time, as the uSDR's shim methods are; `ci16` only, each
sample `[I, Q]` (no `num-complex` dependency, unlike `usdr`'s `Complex<i16>`); new errors
`AlreadyStreaming`, `NotStreaming`, `DoublePumpedMimo`, `UnsupportedPacketSize`,
`Stream`, `Timeout`, `ShortRxBlock`, `ChannelBuffers`, `BufferTooSmall`, and
`ChipMissing` now produced for a dead RX DMA engine. `lms7002m::ctrl::Control::set_siso`
is new public chip-control API. The stream engine's sequences and burst arithmetic are
the new shared `sdr-stream` (public, unpublished), re-exported by `usdr` at its old
internal paths.

*Public API (pending owner review, 2026-10-18): paths, NCOs and corrections.* `Device`
takes libusdr's controls as typed values: `RxRoute`/`TxRoute`/`RfPath` and `Mac`
(re-exported from `lms7002m`) for the paths and channel selections, `IqCorrection`,
`TxGenerator` and `LmlRxMode`; the baseband NCO in hertz (`set_baseband_frequency`, both
channels, as libusdr's path does) beside the raw TX word (`set_tx_nco_word`); new errors
`InvalidPath`, `NcoOutOfRange(hertz)` and `InvalidCorrection`. `lms7002m::ctrl` makes
`ChipCall` and `ChipCalls` (at most 32 calls, else `None`) public so a board composes
its handlers from chip calls as libusdr's `m2_lm7_1.c` does, and its band tables (`RxAntenna`, `TxAntenna`) gain the
loopback switch positions and the TX names, which the LimeSDR's tables also carry (from
`limesdr_ctrl.c`) though no LimeSDR path uses them yet.

*Public API (pending owner review, 2026-10-18):* with every board the XSDR's connector
admits now brought up, `Error::FrontEndNotPorted` and the `FrontEndBoard` re-export (the
type it carried) are gone: fe4ch4007200, the one unported board, cannot answer on the
XSDR, whose transports refuse its I2C core 1 (and the automatic probe reaches it only if
the breakout fails); should one answer, open fails with `Error::FrontEnd(NotPorted)`. `Device` keeps the `sdr_frontend::FrontEnd`
and exposes only its kind (`Device::front_end`); the controls libusdr's `m2_lm7_1`
registers for it are offered since 2026-10-21 (above).
