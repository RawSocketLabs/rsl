# application/cookie

HTTP cookies for a client: a subset of RFC 6265. refcheck protocol name: **`cookie`**.

> Canonical agent-guidance file; `CLAUDE.md` is a symlink to it. The workspace root
> [`AGENTS.md`](../../../AGENTS.md) and protocol guide [`../../AGENTS.md`](../../AGENTS.md)
> also apply.

## Status — dev

`Cookie::parse` reads one `Set-Cookie` header value by the RFC's user-agent algorithm, and a
`Jar` holds the cookies of one scheme and host and writes the `Cookie` header for a request
to it.

Left out on purpose: the `Domain` attribute and everything about which host a cookie belongs
to (a caller keeps one jar per scheme and host), the `Secure` and `HttpOnly` flags,
public-suffix rules, and persistence. Add them when a consumer talks to more than one host
with one jar. Until then, sharing a jar between `http` and `https` of a host would send a
`Secure` cookie in the clear.

## Architecture

- `src/cookie.rs` — `Cookie { name, value, path, expires }`. `parse` follows RFC 6265 §5.2:
  split at the first `;`, then the first `=`; `Path`, `Expires` and `Max-Age` are read,
  `Max-Age` wins, the last of a repeated attribute wins, anything else is ignored.
  `matches_path` is the §5.1.4 path-match; the default path is the request's directory.
- `src/date.rs` — the §5.1.1 cookie-date algorithm, which reads tokens in any order, to
  seconds since the Unix epoch.
- `src/jar.rs` — `Jar`: store, replace in place, delete by expiry, and the §5.4 `Cookie`
  header (longer paths first, then older cookies first).

`#![no_std]` with `alloc`, `#![forbid(unsafe_code)]`, no dependencies, and no bnb: a cookie is
delimited text, like the HTTP head it travels in (see `../http1/AGENTS.md`).

## Rules

- **No clock.** Every time-dependent call takes `now` in seconds since the Unix epoch.
- **Bounded.** A cookie whose name, value and path together exceed `Jar::MAX_COOKIE_LEN` is
  not stored, expired cookies are dropped on every `store`, and a full jar drops its oldest,
  so a server cannot grow a client's memory without limit or push a live cookie out with
  dead ones.
- **`store` refuses what cannot be sent back.** A cookie with a carriage return, line feed
  or NUL in its name, value or path is ignored: written into a `Cookie` header it would end
  the line. `insert` is the raw way in and checks only the size.
- Where the crate does something other than the RFC's algorithm, the item carries a
  `//~ deviates` line with the reason (`date.rs`, `jar.rs`).
- **Forgiving on input, as the RFC requires.** §5.2 says a user agent must parse with its
  algorithm, which accepts more than the grammar servers are asked to follow. A header the
  algorithm says to ignore is ignored; nothing here returns an error for one.
- Names and values are bytes. Nothing is decoded, quoted or validated beyond the algorithm.

## Testing

- **`contract`** — `tests/contract.rs`: the examples of RFC 6265 §3.1 in order, then the
  attribute, storage, path and ordering rules of §5.
- **`adversarial`** — `tests/adversarial.rs`: ignored headers, odd but parseable ones,
  overflow in `Max-Age`, the size and count bounds, cookies that would break a header, and
  generated bytes through every parser.
- **`unit`** — inline in `date.rs`: dates against Python's calendar, older date formats,
  every byte as a delimiter or not, first-match-wins, the range limits, and dates that do
  not exist.
- There is no fuzz target yet; one is owed.

Run: `cargo test -p cookie`.
