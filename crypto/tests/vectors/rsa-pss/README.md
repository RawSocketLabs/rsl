# RSASSA-PSS vector provenance

## Controlling publications

- **Scheme:** RFC 8017, *PKCS #1: RSA Cryptography Specifications Version 2.2*, November 2016,
  §4, §5.2.2, §8.1.2, §9.1.2, Appendix B.2.1. <https://www.rfc-editor.org/info/rfc8017/>.
  Accessed 2026-08-28.
- **Profile:** RFC 8446 §4.2.3 (`rsa_pss_rsae_sha256`: SHA-256, MGF1-SHA-256, salt length equal
  to the digest length); FIPS 186-5 §5.4 (approved PSS parameters) and §5.1 (2048-bit minimum).
- **Hash:** FIPS 180-4 SHA-256, recorded in `tests/vectors/sha256/README.md`.

## Material used

### NIST CAVP RSASSA-PSS

- **Archive:** `186-3rsatestvectors.zip` from
  <https://csrc.nist.gov/projects/cryptographic-algorithm-validation-program/digital-signatures>.
- **SHA-256 of archive as downloaded 2026-08-28:**
  `8405aeb3572a4f98ed4b1a3ccb3f2f49e725462dd28ec4759d6a15d88855d19c`.
- **`SigVerPSS_186-3.rsp`,** CAVS 11.1, generated 2011-05-18: the 18 `SHAAlg = SHA256` cases in
  the `[mod = 2048]` section (`e`, `Msg`, `S`, `SaltVal`, `Result`). That section rotates
  through several moduli, so each case is stored with the `n` that precedes it in the file. NIST's verdicts
  are `P` for three cases and `F (1 - Message changed)`, `F (2 - Public Key e changed)`,
  `F (3 - Signature changed)`, `F (4 - Format of the EM is incorrect - hash moved to left)`, and
  `F (5 - Format of the EM is incorrect - 00 on end of pad removed)` for three each. Each modulus's
  `p`, `q`, and per-case `d` are not used. `SaltVal` is 32 bytes for this group.
- **`SigGenPSS_186-3.txt`,** the `[mod = 2048]` group `n` and `e` and its 10 `SHAAlg = SHA256`
  cases (`Msg`, `S`, `SaltVal`). `SaltVal` is 20 bytes for this group, so these cases exercise
  the explicit-salt-length verifier entry point. `d` is not used.

The archive's readme describes FIPS 186-3 material; RSASSA-PSS verification is defined by
RFC 8017, which FIPS 186-5 §5.4 adopts.

## Conversion policy

Every hexadecimal field is copied into `tests/rsa_pss/*_fixtures.rs` by a mechanical script and
decoded pair-by-pair into its printed big-endian byte order by `tests/rsa_pss/support.rs::decode`.
Wycheproof's modulus retains its leading `00`; NIST's `e` retains its zero padding. Component
import normalizes both. No fixture byte is generated by this implementation.
