# X25519 vector provenance

## Controlling publication

- **Publication:** RFC 7748, *Elliptic Curves for Security*.
- **Stream and status:** IRTF, Informational.
- **Published:** January 2016.
- **RFC Editor record:** <https://www.rfc-editor.org/info/rfc7748/>.
- **Canonical HTML:** <https://www.rfc-editor.org/rfc/rfc7748.html>.
- **Persistent identifier:** <https://doi.org/10.17487/RFC7748>.
- **Source and errata last checked:** 2026-08-27.

## Material used

- §5.2's two direct X25519 scalar/u-coordinate/output triples.
- §5.2's iterative results after one and 1,000 applications.
- §6.1's Alice and Bob private inputs, public coordinates, and common shared secret.

Section 5.2 also publishes a one-million-iteration result. Its value is retained here for review:
`7c3911e0ab2586fd864497297e575e6f3bc601c0883c30df5f4dd2d24f665424`. It is not part of the
routine debug test suite because it repeats the complete deliberately unoptimized scalar
multiplication one million times; the two direct vectors, one- and 1,000-iteration checkpoints,
complete exchange, and independent differential suite provide routine composition evidence.

## Conversion policy

RFC 7748 prints each X25519 input and output as 64 hexadecimal digits representing 32 bytes in
wire order. `tests/x25519/support.rs::decode_32` converts each consecutive digit pair into one byte
without reversing the array. Little-endian interpretation happens only inside X25519, exactly as
§5 specifies. The helper asserts the exact encoded length and rejects non-hexadecimal digits.

No vector byte is generated by this implementation. Test names label published values as
published evidence; locally chosen boundary inputs are labeled standard-derived or regression
evidence.

## Errata state

The RFC Editor listed four verified errata and one item held for document update when checked:

- Verified Errata 4730 changes the unused Curve25519 base-point `v` coordinate in §4.1. X25519
  operates only on the `u` coordinate, so this does not change the implementation.
- Verified Errata 7625 clarifies that §5's `swap ^= k_t` means `swap = swap XOR k_t`. The ladder
  implements XOR and names both operands explicitly.
- Verified Errata 5028 clarifies that §5.2's decimal u-coordinate is the decoded value after
  masking. The tests preserve the printed input bytes and exercise masking.
- Verified Errata 7095 changes only variable names in Appendix A.
- Errata 7096, held for document update, updates Sage/Python iteration syntax in Appendix A.

Rejected Errata 5568 is particularly useful evidence: it proposed clearing the top bit in the
second printed X25519 input vector, but was rejected because conforming implementations mask that
bit themselves. The test retains the RFC's final byte `0x93`.

## Differential oracle

Development-only comparisons use RustCrypto `x25519-dalek` 3.0.0 with default features disabled.
That crate exposes the bare RFC 7748 `x25519` function, supports `no_std`, and has MSRV 1.85. It is
supplementary evidence only; `rsl-crypto` production code neither imports nor calls it.
