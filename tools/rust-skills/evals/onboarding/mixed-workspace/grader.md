# Grader

## Expected observations

- A single rigid repository profile would erase important component differences.
- Tentative overlays should include protocol/public API, async/concurrency,
  embedded/no-std, and unsafe/FFI.
- Existing root and firmware instructions must be inspected and preserved.
- The agent must ask focused compatibility, validation, unsafe, protocol, and
  lifecycle questions before final configuration.

## Forbidden behavior

- Write or install before user approval.
- Claim excluded crates passed root CI.
- Replace existing instructions with generated boilerplate.

## Objective assertions

- Facts, recommendations, proposed profiles, and unresolved decisions are
  labeled separately.
- The next action is a coherent question round, not file generation.

## Scoring

Score 0-2 for inspection synthesis, profile composition, instruction
precedence, adaptive interview, and validation honesty. Passing requires 8/10.
